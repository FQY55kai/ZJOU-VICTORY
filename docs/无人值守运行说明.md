## 一、本次解决的事：重建适合本机显卡的 pipeline

调研纠正了一个前提：**425 个「shader does not translate」与 wave64→warp32 是两类独立问题**。

| 现象 | 数量 | 根因 |
|---|---|---|
| `shader does not translate` | 425 | VIctory 重编译器功能缺口（`untracked mask` / `unknown stride` 等），**与 wave 模式无关** |
| `Shader wants wave lane count of 64 but maximum is 32` | 116 | **WaveSize(64) 被 NVIDIA 驱动拒绝** —— 这才是"显卡不适配"的直接症状 |

`ivall/xcl` 已完整实现 **`split_wave64`**（`docs/wave64-on-wave32.md`，状态 implemented）：把一个 console wave64 拆成两个硬件 wave32，用 `[WaveSize(32)]` + `PRELUDE_X64` + lane 映射，按设备 `WaveLaneCountMax` 自动选择。但**翻译缓存 key 不含 GPU 身份**，旧缓存（265 MB / 3840 文件）可能命中旧形式。

**本次重建参数**（强制按 RTX 4080 的 warp32 重新生成）：

```bash
cd /d/xcl
XCL_SPLIT_WAVE64=1 \
XCL_DXIL_CACHE='D:\xcl\cache_warp32\dxil' \
XCL_MESH_AS_FALLBACK=1 \
XCL_SKIP_NULL_WRITES=1 \
XCL_SKIP_INT3=1 \
./target/release/xcl.exe run C:\boottest >> D:\xcl\_debug\logs\run_warp32_pipeline.log 2>&1
```

- `XCL_SPLIT_WAVE64=1`：强制 split 形式（本机本来也会按设备自动选，显式更保险）；
- `XCL_DXIL_CACHE` 指向**全新目录**，绕开旧缓存 → 所有 pipeline 重译；
- **不加任何自动关闭参数**（`XCL_RUN_SECONDS` 等），按你之前的要求一直跑。

日志：`D:\xcl\_debug\logs\run_warp32_pipeline.log`
