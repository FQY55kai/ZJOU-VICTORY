# 性能账本：怎么量、量到了什么、哪些开关值得开

本文所有数字来自**同一台机器、同一个构建**的实测，方法是上游自带的帧时间转储加上两轮同配置对照。
凡是没有超出噪声带的结论，都写明"未测出"，不写成"无效果"或"有效"。

## 0 结论摘要

| 项 | 结果 | 强度 |
|---|---|---|
| 稳态一帧的形状（Series S 快路） | **68.6 ms**，其中 GPU **0.0 ms** | 实测 |
| CPU 侧三项每帧 O(千) 的扫描 | 描述符表 11,380 张 / 卡上拷贝 24,205 段 / 堆遍历 10,134 槽 | 实测 |
| `VICTORY_INPLACE=1` | 帧时间中位 **98.5 → 73.2 ms（−26%）** | 2+2 轮，超噪声带 |
| `VICTORY_UM_COALESCE_KB=64` | 区间 −91%，上送字节 +41%，帧时间 **未测出差异** | 单轮 |
| `VICTORY_UNWATCHED_FRAMES=2` | 拷贝量未下降（68.1 vs 70.3 MB），**无效果** | 单轮 |
| 测量噪声带 | 计数器 **±5%**，帧时间 **±9%** | A/A 对照 |

## 1 计量器具

上游自带帧时间转储，不必自己埋点：

```bash
VICTORY_FRAMETIME_DUMP=D:/bench/ft.csv     # 或 =1，写到 <cache>\frametime.csv
```

- **37 列 CSV**，`#` 开头是元信息块（版本、标题构建哈希、CPU/GPU/驱动、内存、**以及全部开关**），
  `pandas.read_csv(..., comment='#')` 直接读
- 一行约 1 s，同时给 `frame_ms_max` / `frame_ms_avg`（按 present 实测，与 `ms_per_frame` 不同源，可互校）
- **每次运行会截断**文件，留基线要先 `cp`
- 不要 grep 日志：5 s 一行、带 ANSI 转义、字段靠空格对齐，正则一碰就碎

配套脚本 [`tools/bench/compare.py`](../tools/bench/compare.py)：读两份 CSV，输出计数器对比、
噪声带、以及按场景指纹配对的逐对差。

## 2 A/A 对照：先量噪声，再谈优化

同机、同构建、**同一套开关**连跑两轮（A/A），取进世界之后的帧（`draws > 1000`）：

| 量 | 第一轮 | 第二轮 | 差 |
|---|---|---|---|
| `copies_mb` | 84.2 | 84.6 | +0.4% |
| `textures_mb` | 16.0 | 15.3 | −4.8% |
| `copyback_mb` | 37.4 | 36.5 | −2.4% |
| `card_ranges` | 1,826 | 1,833 | +0.4% |
| `card_fetched_mb` | 47.6 | 48.4 | +1.7% |
| **`ms_per_frame`** | **103.3** | **93.7** | **−9.2%** |

**计数器稳定在 ±5%，帧时间自己就抖 ±9%。** 场景也复现不了：`VICTORY_AUTO_A` 驱动的镜头每轮不同，
两条 `draws(t)` 曲线在采样 160 处是 3,634 对 4,632。

因此判据是：

- **效应 > 20% 才认**（例如 INPLACE 的 −26%）
- **低于 20% 只能说"未测出"**，不能说"无效果"
- 单轮 fps 对比——包括任何仓库 README 里写的数字——都是这个量级的东西，不能当证据

反面教材也记一条：拿 `draws` 做协变量回归，系数是 **−11 ms / 千 draw**（符号反）——draw 多的是
"轻场景"，`draws` 是场景类型的代理，不是成本驱动。R² 0.67 也救不了符号。

## 3 稳态一帧的构成

Series S 快路、5,000 draw 级、`run-perf.sh` 的开关块。上游帧行里的 `copies` 与 `textures`
**是 `preparing` 的内部项**，不是并列项——第一次把三项相加得 92 ms，比 68.6 ms 的帧时间还大，
负数差额才暴露出来。

| 项 | 值 | 备注 |
|---|---|---|
| 帧时间 | **68.6 ms** | |
| `preparing` | 47.4 ms | 其中 `copies` 15.1 ms / 81.9 MB、`textures` 6.4 ms / 13.8 MB、堆遍历 9.1 ms、其余 16.8 ms |
| `copying back` | 22.7 ms / 46.1 MB | |
| GPU | **0.0 ms** | 卡基本全程空闲 |

`heap` 那一列还**不是 `preparing` 的子集**：堆遍历跑在"提前的线程"上（`VICTORY_PASSES_AHEAD`，
默认跟 `VICTORY_THIN`），单帧可以超过 `preparing`——开局有一帧 603 ms，`preparing` 175 ms，
`heap` 423 ms。这也是"第一个 3D 画面一顿一顿"的来源：标题的装饰烘焙阶段按需上传贴图，
单帧被拉到 400–600 ms。

## 4 三项每帧 O(千) 的扫描

计数器口径，进世界后的中位：

| 扫描 | 每帧的量 | 备注 |
|---|---|---|
| 描述符表 | **新建 11,380 张 / 73.7k 槽**，命中仅 1,508（12%） | 另有 34,438 槽从 list 自己的表复制 |
| 卡上拷贝 | **12,212–14,039 个区间**，卡上比较 13,732 片，取回 1,240 片 / 70.8 MB | 等卡 15.5 次 / 7.5 ms |
| 堆遍历 | 1 次 / **12.2 ms**，10,134 个缓冲槽 + 3.6 ms 纹理部分 | 单帧可超 `preparing` |
| list 翻译 | **48,629 次调用 / 帧**，302 ms 线程时间（12 线程） | `VICTORY_THIN` |
| passes ahead | 执行线程为它**等 8.7 ms** | `VICTORY_PASSES_AHEAD=0` 可关 |

## 5 `VICTORY_INPLACE=1`：唯一超过噪声带的开关

机制：窗口所在的标题内存不复制，直接把 `XMemVirtualAlloc` 的私有内存开成 host heap，在上面放一个
buffer——**标题的字节就是 shader 读的字节**。

| 项 | 结果 |
|---|---|
| host 是否接受 | **0 拒绝** |
| 实际放下 | 144 窗口 / **206 MB** |
| 被拒 | **5,732 个**："view memory 或非整块提交的私有内存" |
| `copies_mb` | −16.5% |
| `textures_mb` | −69% |
| `copyback_mb` | −38.6% |
| `card_ranges` | **×13（1,826 → 24,205）** |

帧时间（2 轮开、2 轮关）：

| | INPLACE 开 | INPLACE 关 |
|---|---|---|
| 中位 | 69.2、77.2 | 103.3、93.7 |
| 均值 | **73.2 ms** | **98.5 ms** |

**−26%，在 ±9% 噪声带之外，可以认。** 这正好是老 README 里"真要往下压，只有三条"的第 2 条。

**覆盖面为什么只有 206 MB**：level 1 只覆盖 `XMemVirtualAlloc` 的私有内存，而这个标题的窗口大多落在
页池的 section 视图里（`XMemAllocatePhysicalPages` + `MapViewOfFile3`），那种内存开不成 host heap。
level 2 覆盖标题缓冲，但源码写明**不能与 late wait 同用**，而 `VICTORY_RELAY` 隐含 late wait 3——
所以对这个标题，全量 in-place 这条路当前是关着的。

## 6 两个试过但不必再试的

| 开关 | 结果 |
|---|---|
| `VICTORY_UM_COALESCE_KB=64` | 区间/帧 64,135 → 34,222（−47%），`card_ranges` 24,205 → 2,257（−91%）；但上送字节 59.4 → **104.6 MB（+76%）**，帧时间 69.2 → 77.2（**未测出**）。多出来的字节就是被填掉的间隔本身（3 万次合并多 45 MB，平均 1.5 KB），**不是调小阈值能省下来的**，所以这个值不必再调 |
| `VICTORY_UNWATCHED_FRAMES=2` | `copies_mb` 68.1 vs 70.3（几乎没动），整块拷贝反而 28,104 MB vs 26,488 MB。该开关只管堆遍历里那一路，而 draw 数涨了 25%，**无效果** |

## 7 已经是上游最优形态的部分

三个看起来像杠杆、其实早就开着的东西：

| 开关 | 状态 | 依据 |
|---|---|---|
| `VICTORY_ASYNC_SUBMIT` | **已开** | 判据是 `VICTORY_THIN=1` **或**显式 `=1` |
| `VICTORY_ASYNC_PRESENT` | 已开（默认） | 提交与 present 都在自己的线程上，标题的调用立即返回 |
| `VICTORY_WIDE_BACK` | **已开** | 源码注释写 "On by default"，**上游 `docs/unified-memory` 第 4 节写 off，那一列已经过时** |

最后一条值得记：上游那张开关表的 code default 列已经和源码对不上，查之前要回源码确认
（`crates/victory-gpu/src/shadow.rs` 的 `wide_back()`）。

## 8 下一步

1. 任何调参先做 A/A，拿到这台机器的噪声带，再决定多大效应才算数
2. 用**计数器**判断机制是否生效（bytes、ranges、passes），用帧时间判断值不值——但只认 >20%
3. 要测 5% 级的差异，必须先有**可控场景**（固定机位 / 回放）；现在没有，所以不要假装有
4. 剩下的活都在上游 GPU 侧重构那 85 个提交里（页标记回读、单视图共享大拷贝缓冲、堆同步只处理
   变动槽位、纹理暂存池），那是唯一能动"命令录制 + 内存往返"两项成本的东西
